# No Menu 小程序与 Taplist / POS 对齐说明

日期：2026-09-08

## 结论摘要

当前首页已经基本成立，不建议重做。应保留小程序更简洁的品牌头部、城市选择、门店卡片与“首页 / 我的”结构，只统一色彩、字号、间距、圆角和状态表达。

酒吧详情页的问题主要是卡片比例和文本约束失真，而不是信息不足：图片过宽、标题过小、卡片圆角偏小、长名称与状态标签缺少稳定的 flex 约束，容易在微信渲染环境中挤压或换行错乱。

商家端差距则是产品模型问题：当前小程序把酒单做成了普通商品列表；POS 的核心是固定数量的实体酒头。空位、占用、指定枪号上酒、换酒、移动、交换、售罄、隐藏和撤销都必须围绕酒头槽位实现。只补按钮和样式无法真正对齐。

## 一、统一视觉语言

### 基础色彩

- 页面背景：`#080808`；局部可使用 `#0D0D0D`。
- 主卡片：`#111111`；抬升层 / 弹窗：`#151515`。
- 主文字：`#F5F1E6` / `#F5F1E8`，避免纯白。
- 次文字：约 64% 白或 `#BBB2A1`。
- 弱提示：约 48% 白或 `#7C7467`。
- 品牌主色：琥珀金 `#D39A45`。
- 柔和金：`#C6A875`；深金：`#B88A3D`。
- 分割线：约 8%–14% 的暖白；不要使用亮灰实线。
- 成功：`#7BD88F`；危险：`#FF6B5E`；售罄和隐藏优先通过降低透明度表达。

### 字体与层级

- 英文展示标题使用窄体、强视觉字体（Taplist 使用 Bebas Neue）。
- 中文使用系统无衬线字体，重点靠字号、字重和留白，不靠大量颜色。
- 酒吧名、酒款名是视觉主角；地址、风格、酒厂、ABV 是第二层；状态和说明是第三层。
- Taplist 酒款名目标约 21px / 42rpx，最多两行；当前小程序约 31rpx，视觉偏弱。
- POS 页面标题约 26px，正文约 15px，辅助信息约 13px。

### 间距与形状

- 使用 4 / 8 / 12 / 16 / 24 / 32 的间距系统。
- 消费端页面左右留白约 16–24px；小程序当前首页较宽留白可以保留，但详情页建议对齐 16px / 32rpx。
- 消费端酒款卡片圆角约 20px / 40rpx；当前小程序 24rpx 偏小。
- POS 卡片圆角通常为 12px，控件和底部面板约 12–16px，胶囊按钮使用全圆角。
- 金色只表示主操作、当前选择或重要状态，不能让所有文字和边框都变成金色。

### 消费端与商家端的区别

- Taplist 是“氛围和发现”：大图、大标题、较多留白、信息逐层展开。
- POS 是“高频操作工具”：信息密度更高，列表稳定，动作可预测，危险操作有确认和撤销。
- 两端共享颜色与品牌气质，但不应共享同一种卡片密度。

## 二、Taplist 首页

### 视觉关键点

- 原生 Taplist 使用黑色编辑风格：顶部大号 `TONIGHT`、城市名、氛围图门店卡片和少量琥珀金。
- 门店卡片采用 4:3 封面、暗色渐变遮罩、左下大号门店名、地址与状态摘要。
- 更新状态使用小胶囊和绿色状态点，不抢门店名的层级。
- 原生 Taplist 还包含活动横幅、最近上新横滑列表以及“最新 / 附近”切换，但这些不是当前小程序必须迁移的功能。

### 功能

- 加载城市、当前城市门店以及门店公开酒单状态。
- 城市选择弹层，标记当前城市，并显示各城市门店数量。
- 门店列表默认按最近更新排序。
- 原生 Taplist 在获得定位后支持附近排序、城市不匹配提示、定位拒绝后的设置引导。
- 下拉刷新；加载、失败重试、无门店和未配置状态。
- 点击门店进入酒吧详情页。
- 原生 Taplist 还包含活动、最近上新、搜索和“我的”；本轮小程序可不迁移。

### 对小程序的建议

- 保留当前 `No Menu` 品牌头、城市选择、门店卡片和“首页 / 我的”；首页健康度为“基本正常”。
- 不为对齐而强行加入 `TONIGHT` 大标题、活动、新酒横滑或附近排序。
- 只统一颜色、卡片图片比例、标题字重、状态胶囊、间距和所有空 / 错误 / 加载状态。

## 三、Taplist 酒吧详情页

### 目标视觉结构

1. 顶部为真正的 4:3 全宽封面，而不是固定高度的大图。
2. 图片上有暗色渐变；左上返回，右上保存酒单图片。
3. 下部叠加门店名、酒厂 / 品牌标识、地址、营业时间。
4. 描述、标签和活动位于封面之后；小程序本轮可只保留基本信息。
5. 酒款按“今晚 N 款 / 即将上新 N / 刚售罄 N”分组。
6. 单张酒款卡片左侧固定 92px 左右图片，右侧为信息；整卡最低高度约 110px，圆角约 20px。
7. 酒款名 21px、最多两行；状态标签固定在右上且不可被长标题挤掉。
8. 酒厂 × 联名酒厂、风格、ABV、杯型与价格依层级排列；杯型胶囊允许换行。
9. 售罄卡片整体降至约 55% 透明度。

### 功能

- 加载公开门店、公开酒款和活动。
- 无效门店、未找到、失败重载和空酒单状态。
- 展示门店封面、名称、地址、营业时间、简介、标签和活动。
- 酒款按在售 / 上新、即将上新、刚售罄分组。
- 点击酒款进入酒款详情。
- iOS 原生端支持地址打开地图、关注与上新通知。
- 支持把整张酒单保存为图片；另有附近门店推荐。
- 小程序本轮只需：门店基本信息、三类酒款分组、稳定酒款卡片和杯型 / 价格展示。酒款详情、关注、通知、活动、地图、整图保存和附近推荐可以暂缓。

### 当前小程序详情页的高概率错乱原因

- Hero 使用固定 `690rpx`，目标是 4:3 比例，在不同宽度设备上会失真。
- 酒款图宽度约 `190rpx`，在短卡片中占比过大；文字区被压缩。
- 酒款名约 `31rpx`，比目标明显小，主次层级颠倒。
- 卡片圆角 `24rpx`，比目标 `40rpx` 更硬。
- 长中文名、状态标签和右侧内容之间缺少 `min-width: 0`、溢出隐藏、两行截断和 `flex-shrink: 0` 等约束。
- 仅依赖 `min-height`，图片和正文没有形成稳定的同高约束。
- `gap`、`inset`、`backdrop-filter` 等能力在不同微信基础库上的兼容表现不一致，应对关键布局使用更稳妥的 margin 和 top/right/bottom/left。
- 所有状态共用近似金色样式，没有“即将上新”“售罄”“隐藏”的明确视觉差异，也缺少售罄整卡降透明度。

### 建议的详情页卡片约束

- 卡片：左右布局，`min-height: 220rpx` 左右，`border-radius: 40rpx`，`overflow: hidden`。
- 图片：固定约 `184rpx × 220rpx`，不参与 flex 压缩，使用 cover。
- 正文：`flex: 1; min-width: 0;`，上下居中或均匀分布。
- 标题行：标题容器 `min-width: 0`，两行截断；状态标签 `flex-shrink: 0`。
- 元信息：单行截断；杯型区允许换行。
- 不用固定卡片总高度，让长内容把卡片自然撑高。

## 四、POS 视觉特点

- 黑底、暖白文字、琥珀金操作色，延续 Taplist 的夜间酒吧气质。
- 页面左右通常 20px，卡片约 12px 圆角，细而低对比度的边框。
- 主要操作使用金色实心按钮；次要操作使用暗色或金色描边；删除 / 下架才使用红色。
- 页面不是营销展示，而是稳定、紧凑的运营控制台。
- 状态通过点、短标签、透明度和少量颜色表达，不制造大量高饱和色块。
- 大部分复杂操作放在底部面板；行内只保留最高频动作。
- 商家导航为“酒单 / 商品库 / 门店”，仅在 `ordering_enabled` 时增加“开台 / 订单”。小程序本轮不得把点单相关文案带入关闭点单的租户。

## 五、POS 酒单页完整功能与操作流程

### 页面模型

- 酒单是固定数量的实体酒头槽位 `#1…#N`，而不是“所有已启用商品”。
- 即使没有酒，空酒头也必须显示。
- “全部”展示全部实体酒头；另有“上新 / 售罄 / 隐藏 / 空位”筛选和数量。
- 页面加载店铺、分类和酒款；聚焦时刷新；失败可重试。
- 顶部包含门店名、分享上新、酒头设置（仅 owner）和顾客预览。

### 已占用酒头行

- 显示酒头号、酒款图、酒厂与酒名、风格、状态、隐藏标识。
- 点击酒头号进入移动 / 交换枪号。
- 点击图片或编辑入口修改酒款。
- 高频按钮为“清空”和“换酒”。
- 右侧更多菜单承载低频状态和记录操作。
- 隐藏酒款整行降低透明度。

### 空酒头行

- 显示 `#N`、空酒头和“上酒”。
- 点击后必须围绕这个目标酒头选商品，不能让用户重新手填枪号。

### 上酒 / 换酒主流程

1. 从目标空位或目标已占用酒头进入商品选择面板。
2. 在“可用 / 已下架”中切换，并支持按酒厂、名称、展示名和风格搜索。
3. 过滤已经在今晚酒单上的商品。
4. 选择已有商品：确认目标酒头和初始状态（上新 / 在售 / 即将上新）；若目标被占用，明确提示将替换原酒，原酒仍保留在商品库。
5. 选择已下架商品时先恢复，再加入酒单。
6. 找不到时进入新增商品，并把目标酒头带入编辑页。
7. 新商品先保存商品，再单独执行酒头分配；若分配失败，要明确提示“商品已保存、上酒失败”，避免重试生成重复商品。

### 酒款编辑

- 选择启用分类；当前已使用但随后被停用的分类仍可显示。
- 新增时优先搜索本店已有商品，随后才搜索标准商品池；选择标准商品后复制资料，可解除关联。
- 检测本店重名，避免重复商品。
- 图片从相册选择；支持原图预览、捏合缩放、双击复位、更换和移除。
- 图片支持 JPEG / PNG / WebP，最大 2MB；上传失败时必须区分商品保存成功与图片失败。
- 基本字段：名称、酒厂、最多三个联名酒厂、风格、ABV、国家、描述。
- 酒单状态：上新、在售、即将上新；售罄应通过列表快捷动作设置。
- 售卖规格：生啤 / 听装 / 瓶装 / 试饮 / 其他、名称、容量、价格、默认规格、是否供应；支持添加和删除。
- 规格和价格在 POS 中允许为空；若无价格应给出提醒，而不是阻止保存。
- 商品库进入时只保存商品；从指定酒头进入时保存后直接加入目标酒头。

### 枪号移动与交换

- 点击当前枪号打开全部物理酒头。
- 选择空位：移动到该枪号。
- 选择占用位：交换两款酒。
- 使用乐观更新；失败后回滚并提示。
- 店主可把总酒头数设为 1–99，但不能小于当前最高已分配枪号。

### 状态与更多操作

- 上新可标为在售；其他正常状态可标为上新。
- 标为售罄；售罄可恢复为在售。
- 酒单隐藏 / 设为公开。
- 标为即将上新。
- 调整枪号、编辑酒款、查看状态记录。
- 售罄后出现约 7 秒“撤销”提示，恢复到刚才的状态。
- 状态记录显示前后状态和时间。
- 清空酒头必须确认；只从今晚酒单移除，商品仍保留在商品库。

### 顾客预览

- 直接使用当前本地管理数据生成，不依赖公开接口，因此未发布时也能预览。
- 只显示启用、公开、枪号有效且分类公开的酒款。
- 与顾客端一样分为今晚、即将上新、刚售罄。
- 未发布时显示离线提示；价格展示遵循门店价格公开开关。

### 分享上新

- 默认选择状态为上新的在售酒款；没有时回退为当前在酒头上的酒款。
- 最多选择五款；提示缺图酒款。
- 预览海报，按门店价格模式决定是否显示价格。
- 自动生成群分享文案，并在门店已公开时附公开酒单链接。
- 支持保存高清 PNG 和系统分享。

## 六、POS 门店页功能

### 门店首页

- 显示当前门店、账号角色、发布状态；多门店账号可切换门店。
- 未发布时有明显提示。
- “公开酒单”模块包含多渠道发布和价格展示两个独立开关。
- 快捷入口包含基本信息、常用杯型、二维码与链接、活动、经营数据、员工和账户。

### 多渠道发布

- 开启前做就绪检查。
- 确认后同步公开网页、永久二维码入口和 No Menu 消费端。
- 下线前二次确认，并明确三个渠道都会不可访问。
- 发布状态和价格状态必须分开，不能把“公开”误当作“显示价格”。

### 价格展示

- 默认隐藏。
- 开启时确认“顾客将看到杯型和价格”。
- 关闭时只隐藏顾客价格，不删除规格和后台价格。

### 基本信息

- 门店展示名、城市、商圈 / 区域、详细地址、简介。
- 营业时间可以选择不展示或设置开始 / 结束时间；支持跨午夜。
- 门店标签从后台目录按类别多选。
- 保存后刷新当前门店身份信息并返回。
- 当前 POS 的该页不负责修改封面图，不应在小程序中凭空新增不同的封面流程。

### 常用杯型

- 最多四个模板；名称和容量至少填写一个，不保存价格。
- 酒款编辑时可一键填入，再为具体酒款设置价格。
- 如果小程序要实现 POS 完整酒单编辑，这个入口也应列入本轮范围；否则需要删除编辑页的“一键填入”能力。

### 二维码与链接

- 展示公开酒单 URL，可复制、分享和在浏览器打开。
- 展示门店永久二维码；即使尚未发布也可以保存，但扫码后的顾客页要到发布后才可访问。
- 支持白底预览、保存高清二维码到相册和分享图片。
- 未签发二维码时提示联系 No Menu，而不是临时生成一个会变化的链接。

### 账户

- 展示门店、角色、绑定门店数以及可用的姓名、手机号、邮箱。
- 多门店切换。
- 修改密码：至少六位并二次确认。
- 退出登录。
- 客服、隐私政策、服务条款。
- POS 还有账户删除申请和状态；小程序本轮若只做“基本账户”可暂缓，但发布前要确认微信平台和现有账号体系的合规要求。

### 本轮可暂缓

- 活动管理。
- 经营数据。
- 员工邀请与管理。
- 开台、订单以及所有点单文案。

## 七、当前小程序商家端与 POS 的关键差距

| 模块 | 当前小程序 | POS 正确模型 | 优先级 |
|---|---|---|---|
| 酒单模型 | 已启用商品列表 | 固定实体酒头 `#1…#N`，含空位 | P0 |
| 空位 | “未上酒单”的商品 | 真正未占用的物理酒头 | P0 |
| 上酒 | 直接新建商品并手填枪号 | 先在目标酒头选择已有商品，找不到再新增 | P0 |
| 换酒 | 能力不足 | 固定目标枪号，替换但保留原商品 | P0 |
| 枪号 | 手工输入 1–99 | 选择空位移动、选择占用位交换 | P0 |
| 状态 | 在售 / 售罄 / 清空为主 | 上新、在售、即将上新、售罄、隐藏、恢复 | P0 |
| 误操作保护 | 缺少 | 确认、乐观回滚、售罄 7 秒撤销 | P0 |
| 商品选择 | 商品池入口较深 | 本店已有优先，再到标准商品池 | P0 |
| 编辑模式 | 保存即上酒 | 商品库保存与指定酒头上酒是两个上下文 | P0 |
| 规格 | 至少一个并强校验价格 | 可无规格 / 无价格，给提醒但可保存 | P0 |
| 规格属性 | 信息不完整 | 类型、容量、价格、默认、供应中 | P0 |
| 预览 | 跳公开详情 | 当前草稿预览，提示未发布和价格模式 | P1 |
| 状态记录 | 无 | 状态变化历史 | P1 |
| 分享上新 | 无 | 选最多五款、海报、文案、链接 | P1 |
| 门店设置 | 基本缺失 | 发布、价格、基本信息、杯型、QR、账户 | P0 |

## 八、建议的小程序商家信息架构

- 消费端继续使用“首页 / 我的”。
- “我的”中提供商家入口；登录和选择门店后进入独立管理区。
- 管理区至少有“酒单 / 门店”两个稳定一级入口，不要把所有管理能力堆在“我的”里的普通列表。
- 酒单页以实体酒头为中心；门店页以设置分组为中心。
- 多门店账号必须先明确当前门店，并始终在页头可见或易于切换。
- 权限沿用 POS：酒头总数等 owner-only 能力不要对普通员工开放。

## 九、实施顺序

### P0：先恢复正确模型

1. 修正酒吧详情页 hero 和酒款卡片布局。
2. 把商家酒单改成固定酒头槽位，渲染空位。
3. 打通指定酒头上酒、换酒、清空、移动和交换。
4. 补齐上新 / 在售 / 即将上新 / 售罄 / 隐藏 / 恢复。
5. 对齐商品选择和编辑，明确商品保存与酒头分配的两阶段结果。
6. 建立门店管理区：发布、价格、基本信息、常用杯型、QR / 链接、账户和多门店切换。
7. 对每个页面补齐加载、空、失败、保存中、成功和失败回滚状态。

### P1：完成 POS 体验闭环

1. 本地顾客预览。
2. 售罄撤销和状态记录。
3. 分享上新海报与文案。
4. 图片原图预览、替换、移除和部分失败提示。

### P2：明确暂不迁移

- 活动、附近排序、关注通知、酒款详情、整张顾客酒单保存。
- 经营数据、员工管理、开台、订单。

## 十、验收标准

- 320–430px 等效宽度下，长中文酒名、英文长酒名、无图、多杯型和售罄状态均不破版。
- 首页和详情页共享颜色、文字层级、圆角和状态规则，但保持消费端的大图氛围感。
- 酒头总数为 N 时始终显示 N 个槽位；筛选“空位”只显示未占用物理槽位。
- 已有商品可以直接上到指定空位；换酒不会删除原商品。
- 选择占用枪号会交换，选择空枪号会移动；失败会回滚。
- 清空、售罄、隐藏和发布下线均有符合风险等级的反馈。
- 门店发布与价格展示是两个独立开关，二维码为永久链接。
- `ordering_enabled = false` 时不出现开台、订单或“不可点单”等点单文案。
- 顾客预览在未发布时仍可使用，并清楚显示未发布状态。
