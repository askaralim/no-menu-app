## 用户可见能力

### 今晚 / Tonight

- 按所选城市浏览公开门店、实时酒单、活动和上新。
- 上新 Feed 分为「适合你 / For You」与「全部上新 / Latest」。
- For You 使用用户私人的 TAP 历史生成第一方候选；Latest 按时间提供不依赖个人历史的入口。
- 支持 6×6 联合活动入口、活动详情和活动图片展示。
- 可由用户主动请求「附近」排序；前台位置仅在设备端参与距离计算，不上传精确位置。

### 搜索与公开详情

- 搜索公开酒款、酒厂和门店。
- 浏览酒厂目录与酒厂详情、门店详情与实时酒单、酒款详情、杯型和参考价格。
- 浏览门店公开活动及海报大图。
- 酒款风格使用数据库维护的 `beer_style_en`；英文缺失时回退原始风格，不在客户端按关键词推断。

### 我的 TAP

- 首次记录可创建匿名 Supabase 身份，无需先注册。
- 一款 canonical beer 计为一款；同一酒款在不同门店可保留独立经历。
- 支持单条门店经历删除、整款熄灭、月度回顾和分享图片。
- 可选择 Sign in with Apple 保护并跨设备恢复记录。
- 支持账号和全部记录删除。
- 我的 TAP 是私人饮用历史，不是购买凭证、评分、公开打卡或社交 Feed。

### 关注、提醒与设置

- 私人关注门店列表。
- 支持按门店开启或关闭 iOS 上新通知。
- 中文、English 和跟随系统三种界面语言选项。
- 关于页面提供隐私、合规和匿名使用分析控制。

## 数据与隐私边界

- 公开页面使用 Supabase anon key 和公开 RPC。
- 私人 TAP、关注与账号资料通过认证 RPC 和 RLS 按 `auth.uid()` 隔离。
- 精确位置不上传到 No Menu、Supabase 或 PostHog；App 不请求后台持续定位。
- PostHog 仅在用户同意匿名使用分析后启用。
- 不向 PostHog 发送原始搜索词、姓名、手机号、邮箱、精确位置或完整 TAP 历史。
- 已发布 OTA 包含 Feed shown / impression / opened 等同意后事件；一般列表和卡片曝光仍未实现。
- 地图打开、二维码扫描、分享和推送点击均不能解释为实际到店或消费。
- 缺失图片不得用虚构酒款图片替代；下架酒款可保留在私人历史中。

分析事件与已知缺口见 [CONSUMER_ANALYTICS.md](CONSUMER_ANALYTICS.md)。

## 明确不应承诺的能力

- Beer Route：仍受 gate / kill switch 控制。
- iOS 活动护照、打卡和海报生成：当前由小程序承接。
- 推送打开分析：尚未覆盖。
- 一般列表或卡片曝光：尚未覆盖。
- iOS 编辑门店 TAP 日期：当前仍延后，优先由小程序提供。
- 任何在线购买、点单、支付、预订、配送或库存保证。

## 维护规则

1. 每次生产 binary 或 OTA 发布后更新「发布基线」。
2. 功能只有在生产环境发布并完成最小验收后，才从「未发布」移入「用户可见能力」。
3. 受 gate / kill switch 控制的功能必须保留其限制说明。
4. 官网、App Store 素材、隐私政策和支持话术应与本文边界一致。
5. 新增个人信息处理、分析事件或跨境接收方时，同步评估并更新隐私政策和分析契约。
