# No Menu 1.2.4 — Edge Functions deployment

Do not deploy these functions before the DRINK LOG production SQL succeeds.

## Required Apple values

### `APPLE_TEAM_ID`

Open Apple Developer → **Membership details** and copy the 10-character Team ID.

### `APPLE_KEY_ID`

Open Apple Developer → **Certificates, Identifiers & Profiles** → **Keys**.
Open the Sign in with Apple key associated with the primary App ID and copy its
Key ID.

### `APPLE_CLIENT_ID`

For this native iOS app:

```text
com.nomenuapp.taplist
```

This must match the app bundle identifier and the Client ID configured in the
production Supabase Apple provider.

### `APPLE_PRIVATE_KEY`

This is the complete content of the `.p8` file downloaded when the Sign in with
Apple key was created, including:

```text
-----BEGIN PRIVATE KEY-----
...
-----END PRIVATE KEY-----
```

Apple allows the `.p8` file to be downloaded only once. If it is no longer
available, create a new Sign in with Apple key and use its new Key ID and `.p8`
file. Do not revoke the old key until both Supabase and the Edge Function have
been verified with the replacement.

The generated OAuth client secret currently entered in the Supabase Apple
provider is not the same value as `APPLE_PRIVATE_KEY`.

## Configure production secrets

Preferred method:

1. Open Supabase production project.
2. Open **Edge Functions → Secrets**.
3. Add:
   - `APPLE_TEAM_ID`
   - `APPLE_KEY_ID`
   - `APPLE_CLIENT_ID`
   - `APPLE_PRIVATE_KEY`
4. Paste the `.p8` content as a secret value and save.

Do not add the private key to EAS, the mobile app environment, Git, shell
history, screenshots, or this repository.

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` are hosted
Supabase Edge Function defaults and should not be copied into EAS.

Verify only the secret names:

```bash
cd /Users/askar/Documents/code/demo/no-menu-app
supabase secrets list --project-ref agtujigvxxdppngirqtu
```

## Deployment order

### 1. Database

Run the complete contents of:

```text
taplist-mobile/docs/release/1.2.4-production-drink-log.sql
```

in the production Supabase SQL Editor. Confirm every boolean in the final row
is `true`.

### 2. Edge Functions

From `/Users/askar/Documents/code/demo/no-menu-app`:

```bash
supabase functions deploy merge-apple-account \
  --project-ref agtujigvxxdppngirqtu

supabase functions deploy delete-my-account \
  --project-ref agtujigvxxdppngirqtu
```

Do not pass `--no-verify-jwt`. Both functions operate on private user data and
must require a valid Supabase user access token.

Confirm both deployments:

```bash
supabase functions list --project-ref agtujigvxxdppngirqtu
```

Expected status for both functions: `ACTIVE`.

### 3. TestFlight

Only build and upload 1.2.4 after the SQL and both functions are confirmed.
EAS production variables need only the existing public Supabase URL/key and
PostHog values; Apple private signing material must remain server-side.

## TestFlight verification

Use test records only:

1. Fresh install and point-light one drink as an anonymous user.
2. Protect the record with Apple and confirm it remains visible.
3. Reinstall or use another device with the same Apple account and confirm the
   record is restored.
4. Create a second anonymous record, protect it with the same Apple account,
   and confirm both histories merge without duplicates.
5. Delete an anonymous-only account and confirm the app returns to an empty,
   signed-out state.
6. Delete an Apple-protected account:
   - confirm Apple asks for authorization;
   - confirm deletion succeeds;
   - confirm the app returns to an empty, signed-out state;
   - sign in again and confirm Apple treats it as a new authorization.
7. Check Edge Function logs for `MERGE_FAILED`,
   `APPLE_REVOCATION_FAILED`, or `DELETE_FAILED`.

If deletion reports an Apple revocation failure, do not repeatedly delete or
manually remove the Supabase user. Capture the function log and stop the test.

## Rotation reminder

The OAuth client secret in the Supabase Apple provider expires at most six
months after it is issued. Rotate it before expiry. The `.p8` private key used
by the deletion function does not follow that six-month client-secret lifetime,
but it must be replaced immediately if compromised or explicitly revoked.
