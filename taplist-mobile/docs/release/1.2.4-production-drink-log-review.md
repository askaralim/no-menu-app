## Deployment decision

Do not run `supabase db push` against this project. The linked production
migration history is empty even though the production schema already contains
the application schema.

Use `docs/release/1.2.4-production-drink-log.sql` in the production Supabase SQL
Editor instead. The deployment file:

- runs inside a transaction;
- checks all required dependencies before changing anything;
- uses idempotent table, index, policy, function, and trigger statements;
- restricts client RPC execution to `authenticated`;
- leaves the trigger function unavailable for direct client execution;
- finishes with a query that verifies every new object.

## Expected impact

- Existing public tap-list tables and rows are not deleted, updated, or
  rewritten.
- The new personal-record tables start empty.
- Installing the reconciliation trigger takes a brief metadata lock on
  `public.drinks`. After installation it only performs work when a drink's
  `product_id` actually changes.

## Manual execution

1. Open the production project in Supabase.
2. Open **SQL Editor** and create a new query.
3. Paste the entire contents of `1.2.4-production-drink-log.sql`.
4. Confirm the selected project is production.
5. Run the query once.
6. Confirm every boolean in the final result row is `true`.
7. Do not rerun any older migration bundle and do not use `supabase db push`.

If execution fails before `COMMIT`, copy the complete error and stop. Do not
manually apply only the remaining statements.
