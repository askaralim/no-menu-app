# No Menu 1.2.4 — Edge Functions deployment

Project ref: `agtujigvxxdppngirqtu`

Do not deploy these functions before the DRINK LOG production SQL has completed
successfully.

## 1. Prepare Apple values

Configure these in Supabase Dashboard → Edge Functions → Secrets:

- `APPLE_TEAM_ID`: Apple Developer → Membership details → Team ID.
- `APPLE_KEY_ID`: Apple Developer → Certificates, Identifiers & Profiles →
  Keys → the Key ID belonging to the Sign in with Apple key.
- `APPLE_CLIENT_ID`: `com.nomenuapp.taplist`
- `APPLE_PRIVATE_KEY`: the complete contents of the downloaded `.p8` file,
  including the `BEGIN PRIVATE KEY` and `END PRIVATE KEY` lines.

The `.p8` file can only be downloaded once. Do not put it in this repository,
EAS environment variables, the mobile app, or a chat message.

The Apple OAuth Secret Key already entered in Supabase Auth is a generated
client-secret JWT. It is separate from `APPLE_PRIVATE_KEY`.

`SUPABASE_URL`, `SUPABASE_ANON_KEY`, and `SUPABASE_SERVICE_ROLE_KEY` are
provided to hosted Edge Functions automatically and should not be copied into
the mobile app.

## 2. Deploy in this order

From:

```text
/Users/askar/Documents/code/demo/no-menu-app
```

Run:

```bash
supabase functions deploy merge-apple-account \
  --project-ref agtujigvxxdppngirqtu

supabase functions deploy delete-my-account \
  --project-ref agtujigvxxdppngirqtu
```

Do not add `--no-verify-jwt`. Both functions must require a valid Supabase user
JWT.

Then check:

```bash
supabase functions list --project-ref agtujigvxxdppngirqtu
supabase secrets list --project-ref agtujigvxxdppngirqtu
```

The function list should show both functions as `ACTIVE`. The secrets list
should show all four Apple secret names; it will not reveal their values.

## 3. Required smoke tests

Use a TestFlight build, not Expo Go:

1. Start anonymously and light a drink.
2. Protect the record with an Apple account that has no prior No Menu record.
3. Reinstall or use another device and confirm the record is restored.
4. Create a second anonymous record and protect it using an Apple account that
   already has records; confirm drinks and venues merge without duplicates.
5. Delete an anonymous account and confirm the app returns to an empty local
   state.
6. Delete an Apple-protected account:
   - the Apple authorization sheet must appear again;
   - canceling it must keep the account and records;
   - completing it must delete the Supabase account and local session.
7. After Apple-protected deletion, use Apple sign-in again. Apple should treat
   it as a new authorization rather than silently restoring the deleted No Menu
   account.

If a merge or deletion returns an error, do not manually delete rows or Auth
users. Preserve the account and inspect the corresponding Edge Function log.
