# 竞品 POS 全流程审计（2026-10-20）

> **产品建议已复核。** 本文保留竞品流程观察；原路线图不应直接作为 No Menu 开发优先级。结合当前产品定位、生产采用数据和“不处理支付”的边界后，请以 [`product-grounded-recommendations-2026-10-21.md`](./product-grounded-recommendations-2026-10-21.md) 为准。

## 审计范围

- 设备：iPhone 镜像中的竞品测试账号
- 路径：桌台 → 开台 → 点单 → 确认下单 → 桌台订单 → 收款/折扣；酒头 → 酒头详情 → 新酒上枪；经营 → 流水；设置 → 商品/规格/容量/单据/会员
- 对照：No Menu `mobile/` 当前 POS/门店端代码与数据模型
- 测试数据：创建了桌台 101、2 人、¥49 的测试订单；未执行实际收款、退款、删除或作废

## 总体判断

这款产品最值得学习的不是视觉皮肤，而是它把吧台日常操作压缩成了四个稳定工作区：桌台、酒单、经营、更多。页面始终只突出一个当前任务，次要操作放进底部面板，主操作固定在拇指区。它的产品模型也比我们的当前 POS 更完整：桌台、人数、下单状态、支付明细、折扣原因、酒桶余量和换桶周期都是一等数据，而不是备注或事后推算。

不建议照搬会员付费墙、促销入口或完整支付渠道。这些是商业化结果，不是当前最应优先解决的操作效率问题。

## 流程步骤与健康度

1. **桌台总览 — 良好。** 空台与占用桌使用黑白反差，桌号是最强视觉锚点；占用时间、人数、金额保持在次级层级。风险：底部推广条遮挡末排桌台，灰色小字对比度偏低。
2. **开台与人数 — 优秀。** 点空桌立即出现人数快捷选择，推荐人数与桌台容量同屏；无需先填写顾客姓名。
3. **点单目录 — 良好。** 左侧分类、右侧商品、底部购物车和主按钮始终稳定；加入商品后卡片与分类同时反馈数量。风险：左侧分类列很窄，辅助文字偏小。
4. **下单复核 — 优秀。** “待下单 / 已下单”把临时选择与已送后厨的内容分开，避免误以为加购已生效。
5. **桌台订单 — 优秀。** 加菜、预结单、付款在固定底部动作区；整单操作收进底部面板，主次清晰。
6. **整单操作 — 良好。** 挂单、转桌、修改人数、拆单、作废都围绕真实门店异常场景组织；危险动作单独用红色区分。
7. **收款与折扣 — 优秀。** 应收、实收、找零、支付方式、快捷现金面额在一个屏幕完成；折扣既有数值方式，也强制选择原因，利于审计。风险：未开通渠道仍占据显著空间。
8. **酒头总览 — 优秀。** 酒头、售卖状态、余量升数/杯数、价格和空位在同一列表；这比普通商品列表更贴近吧台心智。
9. **酒头动作与详情 — 优秀。** 促销、售罄、编辑、下枪、同款换桶集中在一个面板；详情同时展示余量、杯数、销售容量、销售额、实收和桶周期。
10. **新酒上枪 — 良好。** 先确定酒头，再选酒款，再补信息/规格；支持搜索、最近下枪与手动新建。空状态会说明下一步。
11. **经营与流水 — 良好。** 今天/近 7 天/近 30 天/自选日期入口简单；实收、订单、杯数、客单价、对账、会员储值、热销商品分层清晰。测试账号无已结账数据，因此排行与异常流水的真实表现未能验证。
12. **商品与基础设置 — 良好。** 商品可售开关、销售渠道、规格价格、打印与常用容量分别管理；常用容量能减少重复录入。
13. **单据与会员 — 中等。** 单据按结账、未结、挂单、退款分类，并可直接继续点单；会员模块说明清楚，但强付费墙会打断首次理解核心价值。

## 最值得 No Menu 学习的 7 件事

1. **把桌台作为开单入口。** 我们当前开台页以进行中订单列表和“客户姓名”开单，缺少空间化桌台、人数和容量。酒吧员工首先想的是“哪桌”，不是“客户叫什么”。
2. **区分待下单与已下单。** 我们现在保存订单后直接覆盖订单明细；竞品把临时购物车和已经确认的商品分开，可显著减少漏单和误操作。
3. **把结账升级为真正的收款。** 当前 No Menu 主要是把订单状态改为 `checked_out`；应补齐应收、实收、找零、支付方式、折扣/附加费、折扣原因和退款流水。
4. **把异常操作集中到整单动作面板。** 优先支持挂单、转桌、改人数、拆单、作废；不要让这些能力散落在多个页面。
5. **建立酒桶生命周期。** 订单按规格容量自动扣减，支持上枪、同款换桶、下枪、售罄、成本录入和批次历史；酒头页直接展示剩余升数和约可售杯数。
6. **让经营看板回答当班问题。** 首页先给实收、订单、杯数、客单价和对账差额，再进入分析；不要让店员从图表里自己推算。
7. **统一底部面板与固定主按钮。** 高频页只留一个主动作，次级操作使用一致的底部面板；这会比单纯调整颜色更明显地提升流畅感。

## 与当前 No Menu POS 的具体差距

| 能力 | 当前实现 | 建议 |
| --- | --- | --- |
| 开台对象 | `customer_name` 为必填，进行中订单为列表 | 新增桌台、区域、人数；顾客名改为可选 |
| 下单状态 | 保存即写入/覆盖 `order_items` | 引入草稿购物车与已下单批次，确认后才进入制作/出品 |
| 订单修改 | 更新时先删除全部明细再重插 | 改为事务/RPC 的原子更新，避免中途失败留下空单 |
| 结账 | 主要更新 `status` 与 `checked_out_at` | 建立 payment/adjustment/refund 流水，不用订单状态代替财务事实 |
| 桌台操作 | 无挂单、转桌、拆单、改人数、作废 | 先做统一整单动作面板，再逐项补数据模型 |
| 酒头库存 | 固定酒头和售罄历史已有；库存扣减迁移明确暂缓 | 用规格容量扣减桶余量，保留人工校准与换桶批次 |
| 经营数据 | 已有营业日、营收、热销、客户与售罄周期 | 增加实收/应收/优惠/退款/杯数/客单价，并从收款流水计算 |
| 导航 | 点单启用时最多出现酒单、商品库、开台、订单、门店 | 面向当班员工收敛为桌台、酒单、经营、更多；商品配置放“更多” |

## 建议路线图

### P0：先补交易闭环

- 桌台/区域/人数数据模型与桌台总览
- 待下单/已下单双状态
- 原子化创建和修改订单
- 收款流水：现金、其他方式、实收、找零、折扣原因

### P1：补门店异常与酒桶闭环

- 挂单、转桌、改人数、拆单、作废
- 上枪/换桶/下枪批次与剩余容量
- 从已确认订单按 `volume_ml × quantity` 扣减库存，并允许校准
- 当班对账、退款和异常流水

### P2：再做扩展经营能力

- 预结单/打印
- 会员储值、会员价、优惠券
- 多渠道售卖与外卖
- 多门店切换与更细权限

## 不建议照搬

- 不复制竞品的品牌样式；No Menu 的深色金色体系和公开酒单能力是差异化资产。
- 不把会员付费、外卖和支付渠道放进第一阶段。
- 不先做漂亮经营图表；没有可靠的 payment/refund/keg 事实表，图表只会放大错误数据。
- 不把所有功能都放到底部 Tab；角色和当班任务应决定入口。

## 可见的无障碍风险与验证边界

- 多处灰色 12–13px 辅助文字可能对比度不足；图标按钮和分类窄栏的触控目标看起来接近最小值。
- 大部分关键状态同时有文字，不完全依赖颜色，这是优点；但售罄/在售的绿色仍需要实测对比度。
- iPhone 镜像无法验证 VoiceOver 标签、阅读顺序、动态字体、键盘焦点、横屏和放大模式，也不能据此声称符合 WCAG。
